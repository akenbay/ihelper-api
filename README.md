# IHelper — backend

JSON API образовательной платформы IHelper. Django 5 + DRF + PostgreSQL, JWT-аутентификация,
деплой через Docker на Dokploy. Фронтенд — отдельное React/Vite-приложение.

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # заполнить SECRET_KEY и DATABASE_URL
python manage.py migrate
python manage.py seed         # демо-данные
python manage.py runserver
```

Без `DATABASE_URL` поднимается SQLite — удобно для тестов и локальной разработки.
В проде используется Postgres из `DATABASE_URL`.

Через Docker (поднимет Postgres рядом): `docker compose up --build`.

Тесты: `python manage.py test` (43 теста: авто-журналы, веса итоговой оценки, права, приглашения,
логин по email, сброс пароля, материалы).

## Роли

| Роль | Логин | Может |
|---|---|---|
| **admin** | да | создаёт/удаляет координаторов; видит всех учеников, тьюторов, группы, любой журнал |
| **coordinator** | да | создаёт/удаляет тьюторов и учеников; группы, состав, смена тьютора; расписание; предметы; баллы за тестирование; журналы для отчётов |
| **tutor** | да | читает профили своих учеников; создаёт записи уроков и ставит оценки; видит журналы только своих групп; база материалов |
| **parent** | да (по приглашению) | **только чтение** журнала своего ребёнка |
| **student** | **нет** | у ученика нет аккаунта — это запись в БД, к которой привязаны журналы |

Права проверяются в двух местах, и оба обязательны: permission-класс (можно ли дёргать ручку)
и `get_queryset()` / queryset FK-полей в сериализаторе (какие объекты видно и на какие можно
ссылаться). Без второго тьютор мог бы отправить запись урока с чужим `journal_id`.

## Ключевая логика

**Авто-создание журналов.** Журнал = (ученик, предмет). При создании группы и при любом
изменении её состава для каждого ученика создаётся по одному журналу на каждый предмет группы:
группа с математикой → 1 журнал на ученика, с математикой и английским → 2.
Триггер висит на m2m-сигнале (`core/signals.py` → `services.sync_group_journals`), поэтому
журналы не разъедутся, каким бы путём группу ни поменяли — через API, админку или seed.
Операция идемпотентна, дублей нет (плюс уникальный индекс `(student, subject)` в БД).

Исключённый из группы ученик **не теряет журнал**: в нём история оценок, поэтому журнал
помечается `is_active=False`. Возврат в группу реактивирует тот же журнал с историей.

**Итоговая оценка** — метод `Journal.calculate_final_grade()`, отдаёт разбивку и итог:

```
уроки 20% + ДЗ 20% + промежуточный тест 30% + итоговый тест 30%
```

Входной тест — диагностический, в итог **не входит**, возвращается отдельным полем `entry_test`.
Все оценки по единой 100-балльной шкале (иначе взвешенную сумму не посчитать); шкала меняется
константами `GRADE_MIN` / `GRADE_MAX` в `core/models.py`. Баллы тестов нормализуются: 25 из 50 → 50.

Ответ содержит два итога: `final_grade` — с пересчётом весов по имеющимся составляющим
(журнал в середине года не штрафуется за то, что итогового теста ещё не было), и
`final_grade_raw` — по полной формуле, где недостающее считается нулём. `is_complete`
показывает, все ли четыре составляющие уже есть.

**Дату урока тьютор не вводит.** `LessonReport` берёт её из `ScheduleEntry` (расписание
составляет координатор). Перенос занятия оформляется комментарием, а не правкой даты.

## API

Все ручки, кроме `/api/auth/*`, требуют заголовок `Authorization: Bearer <access>`.

### Аутентификация
| Метод | Путь | |
|---|---|---|
| POST | `/api/auth/login` | `{username, password}` (в username можно передать email) → `{access, refresh, user}` |
| POST | `/api/auth/refresh` | обновление access-токена |
| GET | `/api/auth/me` | текущий пользователь |
| POST | `/api/auth/password-reset` | запрос ссылки на сброс |
| POST | `/api/auth/password-reset/confirm` | `{token, password}` (token самодостаточный) |
| GET | `/api/auth/invite/<token>` | проверка ссылки-приглашения |
| POST | `/api/auth/invite/accept` | `{token, password, full_name}` → создаётся аккаунт родителя |

### Ресурсы
| Путь | Кто пишет | Кто читает |
|---|---|---|
| `/api/coordinators/` | admin | admin |
| `/api/tutors/` | coordinator, admin | coordinator, admin |
| `/api/students/` | coordinator | tutor (своих), parent (своих детей) |
| `/api/subjects/` | coordinator | все |
| `/api/groups/` | coordinator | tutor (свои), parent (группы детей) |
| `/api/journals/` | — (создаются автоматически) | по роли |
| `/api/lesson-reports/` | tutor | coordinator, parent (своих) |
| `/api/tests/`, `/api/test-results/` | coordinator | tutor, parent (своих) |
| `/api/schedule/` | coordinator | tutor (своё), parent |
| `/api/materials/` | coordinator | tutor |
| `/api/parent-invite/` | coordinator | coordinator |
| `/api/reports/journal/` | — | по роли |

Полезные действия:
- `GET /api/journals/{id}/` — журнал целиком: уроки, тесты, итог с разбивкой
- `GET /api/journals/{id}/final_grade/` — только итог
- `GET /api/groups/{id}/journals/` — все журналы группы
- `POST /api/students/{id}/invite_parent/` — выслать приглашение родителю
- `POST /api/parent-invite/{id}/resend/` — переотправить (старая ссылка гасится)
- `GET /api/reports/journal/?student=&subject=&group=&date_from=&date_to=` — выгрузка журнала
  за период (уроки фильтруются по периоду; итог считается по всему курсу)

## Приглашение родителей

Открытой регистрации нет. Координатор создаёт ученика с `parent_email` и вызывает
`POST /api/students/{id}/invite_parent/`. Генерируется одноразовый токен
(`secrets.token_urlsafe(32)`); в БД лежит **только SHA-256 хеш**, сырой токен уходит
исключительно в письмо и живёт `PARENT_INVITE_TTL_HOURS` часов (по умолчанию 72).
Родитель переходит по ссылке, задаёт пароль → создаётся аккаунт `role=parent`, привязанный
к ученику. Переход по ссылке = подтверждение email, отдельная верификация не нужна.

Если у родителя двое детей — второе приглашение не создаёт второй аккаунт, а привязывает
ещё одного ребёнка к существующему; пароль при этом не перезаписывается (иначе владение
ссылкой означало бы смену пароля чужого аккаунта).

Сброс пароля и приглашение **не раскрывают, существует ли email** — ответ одинаковый в любом
случае (защита от перебора аккаунтов).

## Почта

`core/emails.py` — единственная точка интеграции. Отправка идёт через **Brevo**
(transactional API, `https://api.brevo.com/v3/smtp/email`, обычный `requests`). Три письма:
приглашение, сброс пароля, уведомление родителю о новом отчёте (в уведомлении — только ссылка
на вход, без оценок и фидбека: персональные данные не уходят за границу в теле письма).

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `BREVO_API_KEY` | ключ Brevo. **Задан** → письма уходят через Brevo; **пустой** → откат на Django `EMAIL_BACKEND` (в деве `console`, письмо в лог) |
| `DEFAULT_FROM_EMAIL` | отправитель; должен быть verified sender в Brevo. Формат: адрес или `Имя <адрес>` |
| `FRONTEND_URL` | домен фронтенда для ссылок в письмах (`/invite/<token>`, `/reset-password/<token>`, `/login`) |

Отправка никогда не роняет запрос: при ошибке Brevo (плохой ключ, сеть, rate limit) ошибка
логируется, функция возвращает `False`, а приглашение/токен уже созданы и возвращаются в ответе
API — их можно передать вручную как fallback.

## Деплой (Dokploy)

1. Postgres провижинится в Dokploy, строка подключения кладётся в `DATABASE_URL`.
2. Переменные окружения — по `.env.example`: `SECRET_KEY`, `DEBUG=False`, `ALLOWED_HOSTS`,
   `DATABASE_URL`, `CORS_ALLOWED_ORIGINS` (домен фронтенда), `FRONTEND_URL`.
3. Build: `Dockerfile` (multi-stage, python:3.12-slim). `collectstatic` выполняется при сборке,
   статику отдаёт WhiteNoise. Контейнер работает не под root.
4. **Release-команда (обязательно):** `python manage.py migrate`
5. Запуск: `gunicorn ihelper.wsgi --bind 0.0.0.0:8000` (в `CMD` образа).
6. Health-check: `GET /health/`.

Админ создаётся вручную: `python manage.py createsuperuser`, затем в `/admin/` проставить
`role=admin`. Либо `python manage.py seed` на деве.

## Демо-данные

`python manage.py seed` — 1 админ, 2 координатора, 3 тьютора, 5 учеников с родителями и
SVC-категориями, предметы (математика, английский), «Группа 5А» (оба предмета) и «Группа 6Б»
(только математика), 8 авто-созданных журналов, расписание, входные/промежуточные/итоговые
тесты с баллами, записи уроков с темами, посещаемостью, оценками и фидбеками на русском.
Пароль всех демо-аккаунтов — `ihelper2024` (только для дева). Команда идемпотентна.

## На будущее: вторая организация (СДФ)

Модель `Organization` заведена, поля `organization` на `User`, `Student`, `Subject`, `Group`
есть и nullable — сейчас не заполняются, работаем как одна организация. Когда организаций
станет две: проставить `organization` и добавить `.filter(organization=request.user.organization)`
в `get_queryset()` вьюсетов. Места помечены комментарием `ORG-SCOPE` в `core/models.py`,
`core/views.py` и `core/scoping.py`.
